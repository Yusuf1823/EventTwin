1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
EventTwin is an operational geospatial digital twin and predictive simulation 
platform designed for municipal authorities, mega-event organizers, and emergency 
dispatchers. When massive crowds (500,000+ attendees) converge upon a metropolitan 
precinct (e.g. Jio World Convention Centre, Bandra Kurla Complex, Mumbai), urban 
systems routinely choke in silos:
  - Turnstile bottlenecks trap tens of thousands at entry gates.
  - Metro platforms reach dangerous overcrowding thresholds.
  - Access roads experience vehicular gridlock.
  - Peripheral facilities (Zone C Kalina Hub) sit underutilized with thousands of open bays.

EventTwin unifies verified real-world infrastructure data with a live Neural 
Network (brain.js) and mathematical simulation to detect bottlenecks 45+ minutes 
in advance, model non-linear cascade ripple effects (monsoons, transit strikes, 
gate delays), and compute spatial rebalancing interventions that preserve conservation 
laws while lowering urban stress.


2. TECHNOLOGY STACK
--------------------------------------------------------------------------------
Frontend:
  - Framework: React 19.2 (SPA Architecture)
  - Language: TypeScript 6.0 (Strict Typing, Zero Type Errors)
  - Build Tool / Bundler: Vite 8.3
  - Styling: Tailwind CSS v4.3 + Custom Glassmorphism UI tokens
  - Geospatial Real Map: MapLibre GL 6.10 (Vector/Raster tile rendering, custom animated HTML markers, arterial GeoJSON mobility corridors, Fullscreen API)
  - Map Tile Provider: ESRI World Dark Gray Canvas (Base & Reference labels) for watermark-free, high-contrast night ops telemetry
  - Data Visualizations: Recharts 3.10 (ComposedCharts, AreaCharts, BarCharts, LineCharts)
  - Icons: Lucide React 1.46
  - Interactions: Canvas Confetti 1.9

Backend & Machine Learning:
  - Runtime: Node.js (v20.15.0+)
  - Framework: Express.js 4.21 (RESTful API, modular controllers)
  - Machine Learning Engine: brain.js Neural Network (16 input -> 26 hidden -> 16 hidden -> 3 output)
  - ML Pipeline: Custom training CLI (trainModel.js) with min-max normalization (norm_params.json) and persistence (model_weights.json, model_metrics.json)
  - Simulation Engine: Pure mathematical micro-simulation engine (server/simulationEngine.js)
  - Storage & Sync: Firebase Realtime Database (eventtwin-36665-default-rtdb) with transparent in-memory fallback
  - Testing & Validation: Custom automated test harnesses (test_simulation.js, test_e2e_api.js, test_prediction_service.js, riskClassifier.test.js)

5. API SPECIFICATION
--------------------------------------------------------------------------------
GET  /api/events                - Returns canonical event state (Stress %, loads, visitor count)
GET  /api/digital-twin          - Returns all 15 infrastructure facilities + event summary
GET  /api/venues                - Returns venue facilities (JWCC BKC)
GET  /api/hotels                - Returns 6 verified Mumbai hotels with occupancy
GET  /api/transit               - Returns 4 transit hubs (BKC Metro Line 3, Bandra, Kurla, CSMIA)
GET  /api/parking               - Returns 3 parking hubs (JWCC On-Premises, Kalina, Bandra)
GET  /api/shuttles              - Returns shuttle corridors (Kalina-JWCC Express)
GET  /api/predictions          - Multi-horizon forecasts (15/30/45m), 7 resources, risk labels, nextCriticalEvent, source ('ml' | 'fallback-simulation'), and modelMetrics
POST /api/predictions/scenario - What-If predictive forecast: simulation state -> ML/fallback -> resource forecasts, contributors, and modelMetrics
GET  /api/alerts                - Returns dynamic anomaly alerts generated from state
GET  /api/weather               - Returns live real-time Open-Meteo weather telemetry for BKC Mumbai
POST /api/weather/refresh       - Invalidates weather cache and pulls fresh live atmospheric data
GET  /api/social-signals        - Returns real-time weather-correlated social intelligence signals & traveler sentiment
POST /api/simulation            - What-If engine: computes unmitigated & mitigated states, cascading hospitality matrix, and probabilistic uncertainty
POST /api/interventions/simulate - Simulates rebalancing, updates canonical state & persists to Firebase
POST /api/event-config         - Saves event setup to Firebase RTDB and re-initializes canonical state
GET  /api/event-config          - Returns active event configuration
POST /api/digital-twin/reset    - Resets canonical state back to baseline
